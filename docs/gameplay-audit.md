# AI 狼人杀整体审查与优化

审查日期：2026-10-04。范围为当前 12 人预女猎白、单真人 + 11 AI 的实现。保留原有账号、模型池和数据结构，在已有工作上落实规则、上下文和前端改造。

## 1. 核心判断

沉浸感的主要问题有三类：信息不对称存在漏洞；操作和阶段衔接不够可靠；AI 的记忆过于概括，公开宣称容易和事实混在一起。单纯增加“像真人说话”的提示词无法解决这些问题，因此先修复信息边界和流程，再让每个 AI 带着自己的证据、承诺和性格接话。

前端从滚动日志窗口改为“月下村庄”圆桌：玩家先看到谁在说话、轮到谁、票投向谁，再按需看原话与自己的笔记。

## 2. 已修复的玩法与流程问题

| 优先级 | 原问题及影响 | 落实的修改 |
| --- | --- | --- |
| P0 | 夜死 WebSocket 数据携带真实死因，遗言提示也直接告诉 AI 被刀／被毒，破坏信息不对称 | 公共消息只给按座位排序的死亡名单；AI 遗言只知道“夜间死亡，死因未公开”，技能是否可用仍由引擎按真实原因结算 |
| P0 | 事件接口未指定 seat 时可能返回全量，其他账号也可能获得房主视角 | REST 和 WebSocket 校验真人与对局的归属；进行中只能查看自己的可见事件，不能指定其他座位窥视；结束后才开放复盘全量信息 |
| P1 | 人类操作只靠客户端约束，陈旧操作、任意目标和非法用药可能进入引擎 | 每次操作有唯一 prompt_id；服务端校验当前阶段、角色、布尔类型、存活合法目标、药剂和警徽；错误操作不会消费当前回合 |
| P1 | 推送 prompt 后才建立 Future，快速回答可能丢失；重复提交可能跨回合 | 先建立待答状态再推送；操作确认有 action_accepted；前端等待确认、禁用重复按钮，未连接时保留草稿 |
| P1 | 游戏事务在等待真人时长时间不提交，SQLite 写锁阻塞登录和新建对局 | 通知前提交阶段和事件，释放写锁；结算后的逐人经验更新也立即提交，不占锁等待下一模型；实测此前会出现 database is locked，修复后完整模拟对局期间正常 |
| P1 | 旧 WebSocket 的断连或发送失败会误删新连接 | 断连清理绑定具体 socket；重连发送权威牌面、个人事件、发言顺序、当前发言和待操作请求 |
| P1 | 重复 start 可启动多套游戏循环 | 启动加锁，先保存 running 再启动任务，重复请求拒绝 |
| P1 | 状态机先警上后夜间，与实际首日流程不符 | 调整为先夜间技能，再首日竞选、夜间结算；补充日夜胜负检查分支 |
| P1 | 单候选人仍投票；PK 玩家参与复投；弃票容易被当成目标 | 单候选人自动当选；台上 PK 玩家不能复投；保留每人弃票记录，但计票忽略 null，全弃票无人出局 |
| P1 | 警上自爆后仍可能进行当日讨论和投票，PK 竞选阶段未覆盖自爆 | 竞选演说含 PK 都可自爆吞徽；结算夜间死亡、遗言与技能后跳过当日投票进入下一夜 |
| P1 | 警长死亡未指定接徽目标会保留无效警长 | 未选择转移按撕徽处理，移徽只给合法存活玩家 |
| P1 | 真人超时被阶段异常捕获，可能继续执行不完整对局 | 专门传播 GameTimeoutError，由主循环结束超时对局 |
| P2 | 复盘把白痴首次免死显示成投票出局，撕徽未进入时间线 | 区分翻牌免死与实际死亡，兼容旧事件记录；补齐撕徽摘要 |
| P2 | 不允许连续刀同一目标的额外限制与当前板子提示不一致 | 移除该限制，允许自刀和连续刀，提示词与引擎一致 |
| P2 | 白天提示未正确获得昨晚死亡座位 | 根据当前轮的死亡记录构造名单；不推断未公开死因 |

当前固定板子采用首夜遗言、首夜可自救、一晚一药、白痴免死与屠边等规则。不同 App 的房间规则可能不同，因此局内规则说明明确展示本项目选择，避免玩家依赖其他平台的默认习惯。

## 3. 每个 LLM 的 Context 管理

### 3.1 按玩家隔离，不按模型共享聊天

`GamePlayer.model_name` 决定该座位调用的模型。`LLMClient` 的缓存只是连接与模型配置；每次调用只发送重新构造的 system + user 消息，不让两个座位共享历史会话。

2026-10-05 补充：截图里第一夜的「7号刚才说……」来自旧 UI 模拟器的固定台词，不是实际模型回复。现已将模拟器移入 `scripts/`，按阶段生成不引用虚构历史的样例，并在页面标记模拟模式。真实模型第一夜的模板明确禁止引用不存在的公开发言；跨局习惯在读入和保存前过滤包含座位号、轮次或上一局时序引用的句子。该规则能去掉明确的局内引用，不能替代对自由文本含义的真实模型评测。

`GameManager._get_memory_summary()` 先从数据库读取该身份可见事件，`ai/mind.py` 再做一次防御性过滤：好人拿不到狼队事件；任何人拿不到别人的内心独白；system 事件不作为玩家记忆。

上下文按以下信息构成：

| 信息 | 保留策略与认知边界 |
| --- | --- |
| 我的技能结果 | 查验、自己的用药等直接事实优先保留；不从别人宣称推导真实身份 |
| 公开结果 | 死亡、票型、警徽、猎人开枪、白痴翻牌；夜死不自动认作狼刀或好人 |
| 其他人的宣称 | 标注“尚未证实”，配最近原话；金水、查杀、神职宣称可能是谎话 |
| 近期发言 | 优先保留当前轮和上一轮的原话，按预算从近到远取，再恢复时间顺序 |
| 我说过什么 | 保留最早重要承诺和近期发言，帮助维持站边、警徽流和改判解释 |
| 我之前怎么想 | 只保留自己的近期主观判断，明确允许它出错，不升级为事实 |
| 狼队计划 | 狼人保留最近讨论，提醒是私密信息，避免丢失分工和悍跳计划 |
| 跨局习惯 | 用户级经验压缩成简短打牌习惯，不携带上一局座位、角色或具体玩家关系 |

默认个人记忆预算为 6500 字符；这是字符预算，不是 token 预算，必要技能与公开事实优先，极端情况下允许超过预算。阶段模板里的近期发言每条限制 500 字、列表最多 24 条。整份请求目前没有按每个模型 tokenizer 做硬性上限；后续可以进一步去掉记忆与阶段发言的重复片段。

原 `memory_compressor.py` 的 LLM 压缩不在实际游戏调用路径中，文档已修正，当前采用确定性个人记忆组装。这样不会为了压缩再让另一模型重新解释技能事实。

### 3.2 模型配置检查

以下是当前代码的调用配置。2026-10-05 的补充验证逐一调用了 14 个模型的虚构开局；这只验证当时的请求适配，不代表完整对局质量或长期可用性。

| 模型组 | 平台 | JSON / 思考适配 |
| --- | --- | --- |
| 千问 3.7 Plus、3.7 Flash、3.8 Flash、3.8 Max | 百炼 | JSON mode，关闭混合思考 |
| Kimi K3 | 百炼 | JSON mode，保留强制思考；固定 temperature=1.0，输出额度至少 8192 |
| GLM 5.2 | 百炼 | JSON mode，关闭混合思考 |
| GLM 5.3 | 百炼 | JSON mode，低强度思考，输出额度至少 2048 |
| MiniMax M2.5 | 百炼 | 不发送不支持的 JSON mode 参数，提示约束 JSON 后解析；输出额度至少 4096 |
| DeepSeek V4 Flash（`deepseek-v4-flash-0731`）、V4 Pro | 百炼 | JSON mode，关闭混合思考；不能按 deepseek 前缀误路由到火山。无日期后缀的 `deepseek-v4-flash` 已下线 |
| 豆包 Seed Lite、Pro、Evolving，以及 DeepSeek V4.1 Flash | 火山方舟 | 明确路由名单，thinking.type=disabled |

14 个模型共享相同的玩家视角、规则与行动校验策略，每局抽取 11 个不同模型。所有请求默认 45 秒超时，SDK 不额外叠加重试，决策最多尝试两次。结构错误会得到修正要求，但错误回答本身不进入下次上下文，以免幻觉变成证据。

投票回退为弃票；预言家、狼人等必须选择目标的行动从合法目标中随机选，避免长期偏向最小座位。女巫回退不使用药。新增模型决策日志记录 seat、model、action、context_chars、尝试数、耗时和 fallback，不记录私密 prompt 正文。

### 3.3 拟人性改动

- 将冗长通用攻略压缩为必要规则、本人信息和认知边界，减少每轮“复述教学材料”。
- 11 种人格影响语气和风险倾向，同名 AI 跨局保持人格；好人的性格不能授权它虚构技能。
- 公开发言通常 2–6 句、80–180 字，上限 250 字；优先回应和自己相关的一两句话，再表达本轮立场。
- 前置位允许留判断，后置位回应已发生的发言；允许直觉、犹豫和误判，不要求所有 AI 永远正确。
- 改判需要解释新证据，不强迫 AI 为了“前后一致”坚持错误判断；也不把被怀疑直接等同于对方是狼。
- 狼人允许有意编造查验与悍跳，好人只报告真正掌握的技能。秘密可以主动公开，但不能被系统无意泄露。
- 玩家语料即使包含“忽略规则”也只当作游戏素材；最终合法行动要求单独附在模板末尾。

这些是输入结构与行为约束的改善。模拟 AI 的发言用于 UI 和流程验收，不能证明真实模型已经稳定达到真人水准。

## 4. 前端体验改造

参考 [网易狼人杀官方产品](https://langrensha.com/) 和 [饭狼产品资料](https://apps.apple.com/cn/app/饭狼-官方正版狼人游戏-派对推理手游/id1607228195) 中的经典推理桌游定位与语音社交体验，结合本项目单人文字对局，采用原创“月下村庄”视觉。没有照搬产品素材或声称已经实现语音功能。

| 区域 | 新体验 |
| --- | --- |
| 大厅 | 林地月夜主题、清晰的入座入口、板子说明、对局记录与复盘入口 |
| 座位 | 电脑圆桌，手机两排 6 席；本人、警长、发言者、出局状态、狼队信息明确区分 |
| 发言 | 当前发言焦点、AI 思考状态、发言顺序、聊天卡片、轮次／关键事件筛选 |
| 票型 | 一张卡片展示投票流向与加权票数，弃票保留；刷新后的历史仍重建票型卡片 |
| 操作 | 选择目标后确认再提交、倒计时、字数提示、快捷发送、提交中锁定与服务端应答 |
| 推理簿 | 点击玩家查看最近原话、标记偏好／偏狼／神职，自由笔记按账号和对局保存在本机，不发送给 AI |
| 回看与重连 | 回看历史不强行滚到底，出现新消息时给跳转入口；重连恢复当前阶段、牌面与合法待操作 |
| 设备与依赖 | 移动布局、可见键盘焦点、减少动画设置；移除字体与 CSS CDN 依赖 |

AI 与玩家发言按文本渲染，昵称、模型和结算中的动态字段做转义，避免游戏语料被浏览器当作 HTML 执行。

桌面验收尺寸 1280 × 800，手机 390 × 844，结束后已恢复浏览器默认尺寸。已实际操作上警选择、警长选票与确认、刷新恢复发言、输入发言、查看玩家、保存并恢复标记／笔记、打开规则。

桌面和手机界面截图含有本地账号昵称，未放入公开仓库。验收使用临时数据库和确定性模拟 AI。

### 2026-10-05 Kimi 预言家整局回退修复

- 旧服务日志中 Kimi K3 的正常行动收到明确 HTTP 400：`Parameter 'temperature'=0.75 is not supported for kimi-k3 model`。这发生在供应商处理请求参数时，模型没有生成决策；反复重试同一参数自然仍然失败。
- 原适配还把 Kimi K3 当成可关闭思考的混合模型。根据[百炼 Kimi 官方文档](https://help.aliyun.com/zh/model-studio/kimi-api)，K3 仅支持思考模式，默认温度为 1.0。现在使用固定 1.0、不传 `enable_thinking=false`，并为思考和最终 JSON 留至少 8192 输出额度。单轮与多轮请求共用适配；供应商标记 `finish_reason=length` 时，不把截断的推理内容当作已完成决策。
- 修正上警回退动作的阶段名称与布尔字段。技术失败时预言家默认上警，其他角色默认不上警，退水失败默认保留参选；正常模型输出仍按自身选择执行。没有换掉 Kimi，也没有修改旧局角色或发言。
- 虚构预言家场景真实验证 Kimi：首夜选择查验 7 号，测试角色分配结算为好人；上警返回 `run=true`，竞选发言报 7 号金水，白天正常发言。四个阶段均通过校验，最终均未回退。[结果](kimi-seer-eval-20261005.json)。测试不读取实际对局或跨局经验。白天发言曾首请求超时，第二次成功；结构通过不代表所有语义和策略都正确。
- 使用相同的生产适配、虚构平民开局，逐一测试配置池的 14 个模型，14 个均返回合法上警决策且最终未回退。[结果](model-compat-eval-20261005.json)。3 个千问样本首请求超时，重试成功。这只证明当时接受请求和生成合法 JSON，不是长期可用性保证。
